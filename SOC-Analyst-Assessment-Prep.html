00استراتيجية الـ Assessment — إزاي تفكر وتكتب الإجابة

الـ Assessment بتاع SOC مش بيختبر إنك حافظ Event IDs وبس، هو بيختبر طريقة تفكيرك: هل بتبني استنتاج على دليل؟ هل بتعرف تفرّق بين الـ noise والـ real threat؟ هل بتعرف تكتب Report مفهوم لحد مش تقني؟

المنهجية الذهبية لأي سؤال تحليل (Triage Loop)

  1. Understand the alert: إيه اللي حصل؟ مين (user/host)؟ إمتى (timestamp + timezone)؟ منين لفين (src → dst)؟
  2. Collect evidence: استخرج كل الـ IOCs (IPs, domains, URLs, hashes, emails, filenames, user-agents).
  3. Enrich: اعمل lookup للـ IOCs (VirusTotal, AbuseIPDB, urlscan, WHOIS — عمر الدومين؟).
  4. Correlate: اربط بين مصادر مختلفة: Email → Proxy (حد داس؟) → EDR (حاجة اتنفذت؟) → Firewall/DNS (فيه C2؟).
  5. Verdict: True Positive / False Positive / Benign True Positive / محتاج Escalation — مع السبب.
  6. Scope & Impact: كام user/host اتأثر؟ فيه data خرجت؟ الـ account اتسرق؟
  7. Response: Containment (isolate, block, reset, purge) + Eradication + Recovery + Lessons learned.
💡 شكل الإجابة اللي بيبهر اللي بيصحح لما تجاوب أي سؤال تحليل اكتبه بالترتيب ده (حتى لو مش مطلوب): Summary (سطرين) ← Evidence / Findings (bullets بدليل من اللوج) ← IOCs (defanged) ← MITRE ATT&CK mapping ← Verdict + Severity ← Recommendations (Immediate / Short-term / Long-term).

قواعد ذهبية لازم تبان في إجاباتك

✅ اعمل

  • Defang أي IOC: hxxps://evil[.]com و 203.0.113[.]5
  • اذكر الـ timestamps وخلي بالك من الـ timezone (UTC vs local).
  • استشهد بالسطر نفسه من اللوج ("السطر 7 فيه POST لـ login.php بحجم 2KB…").
  • قول الـ assumptions بتاعتك صراحة لو المعلومة ناقصة.
  • فرّق بين attempt و success (Status code، bytes، follow-up activity).
  • اقترح next steps: "هشيك على EDR للـ host ده في نفس الوقت".

❌ ماتعملش

  • ماتقولش "malicious" من غير ما تقول ليه.
  • ماتعتمدش على VirusTotal = 0 detections إن الحاجة نضيفة (ممكن جديدة).
  • ماتفتحش لينكات/attachments على جهازك — sandbox بس.
  • ماتعتبرش SPF pass = إيميل آمن (الهاكر ممكن يكون عامل SPF لدومينه).
  • ماتعملش Upload لملف فيه بيانات الشركة على VirusTotal (Hash lookup الأول).
  • ماتنساش تتكلم عن الـ Business impact.

TCP vs UDP

TCP — Connection-oriented

  • 3-way handshake، Reliable، Ordered، Retransmission
  • أمثلة: HTTP/S, SSH, SMB, RDP, SMTP
  • في اللوج: تقدر تعرف هل الـ connection اكتملت ولا لأ

UDP — Connectionless

  • سريع، بدون ضمان وصول، بدون handshake
  • أمثلة: DNS (53)، DHCP، NTP، SNMP، Syslog، VoIP، QUIC
  • سهل يتعمل بيه Spoofing و Amplification DDoS

HTTP — اللي لازم تعرفه للتحليل

Methods

  • GET طلب بيانات (الـ parameters في الـ URL ← بتبان في اللوج)
  • POST إرسال بيانات (الـ body مش بيظهر في access log عادةً) — Login، Upload، Exfil
  • PUT / DELETE رفع/مسح resource — لو مفعّلين غلط = خطر
  • HEAD / OPTIONS استطلاع — كتير بيستخدموا في الـ Scanning
  • CONNECT عمل Tunnel عبر Proxy (HTTPS)

Status Codes

  • 2xx نجاح: 200 OK، 201 Created، 204
  • 3xx Redirect: 301 دائم، 302 مؤقت (بعد Login ناجح كتير!)، 304 Not modified
  • 4xx خطأ عميل: 400، 401 unauth، 403 forbidden، 404 (كتير = Dir brute force)، 405، 429 rate-limit
  • 5xx خطأ سيرفر: 500 (مع SQLi = الـ payload كسر الـ query!)، 502، 503

Headers مهمة: Host، User-Agent (sqlmap/curl/python-requests/PowerShell = مريب)، Referer (جاي منين؟)، Cookie، X-Forwarded-For (الـ IP الحقيقي ورا proxy/LB)، Content-Type، Authorization.

TLS / HTTPS باختصار

Client Hello (فيه الـ SNI = اسم الدومين بيظهر cleartext) ← Server Hello + Certificate ← Key exchange ← Encrypted traffic. فايدة للـ SOC: حتى لو مش شايف المحتوى تقدر تشوف: SNI، الـ Certificate (self-signed؟ Let's Encrypt جديد؟)، JA3/JA4 fingerprint للعميل (Cobalt Strike مثلاً ليه fingerprints معروفة).

بروتوكولات تانية سريعة

  • ARP: IP ← MAC داخل الـ LAN. ARP Spoofing = MITM (لو شفت MAC واحد لـ IPs كتير أو gateway MAC اتغير).
  • DHCP (DORA): Discover → Offer → Request → Acknowledge. مفيد لربط IP بـ Hostname في وقت معيّن!
  • NAT/PAT: IPs داخلية كتير تطلع بـ Public IP واحد ← عشان كده لازم Firewall/NAT logs عشان تعرف مين الجهاز الحقيقي.
  • ICMP: ping (Type 8 request / 0 reply)، Type 3 unreachable. Payload كبير/غريب = ICMP tunneling.
  • VLAN / Segmentation: بيقلل الـ Lateral movement.
  • Forward Proxy (بيحمي الـ users وهم طالعين للإنترنت) vs Reverse Proxy (قدام السيرفرات: Load balancing، WAF).

SPF / DKIM / DMARC — الشرح اللي هتحتاجه

SPF

"مين الـ IPs/السيرفرات المسموح لها تبعت باسم الدومين ده؟" — TXT record. بيتشيك على دومين الـ Return-Path (مش From!).

v=spf1 ip4:192.0.2.0/24 include:spf.protection.outlook.com -all

-all Fail (رفض) · ~all SoftFail · ?all Neutral · +all أي حد (كارثة)

DKIM

توقيع رقمي على الـ headers والـ body بالـ Private key للدومين، والـ Public key في DNS. بيثبت إن الإيميل ماتعدّلش وإنه من الدومين اللي في d=.

DKIM-Signature: v=1; a=rsa-sha256;
 d=company.com; s=selector1; ...
→ selector1._domainkey.company.com

DMARC

بيربط النتيجتين بدومين الـ From (Alignment) ويقول تعمل إيه لو فشل:

_dmarc.company.com TXT
"v=DMARC1; p=reject; rua=mailto:dmarc@company.com"

p=none مراقبة بس · quarantine Spam · reject رفض

⚠️ أهم نقطة يسألوا فيها SPF/DKIM/DMARC = PASS ≠ الإيميل آمن. الهاكر ممكن يشتري دومين micros0ft-support.com ويظبطله SPF و DKIM و DMARC صح، فكله يعدي Pass. اللي بيثبتوه إن الإيميل فعلاً جاي من الدومين ده — مش إن الدومين نفسه شرعي. ونفس الكلام لو الإيميل من حساب Gmail أو حساب حقيقي اتسرق (Compromised account).

  1. Sender analysis: Display name vs email address؟ الدومين Lookalike؟ (عمره كام يوم — WHOIS). Reply-To / Return-Path مختلفين؟
  2. Authentication: SPF / DKIM / DMARC نتايجهم؟ و Alignment؟
  3. Received chain: الـ Originating IP إيه؟ سمعته (AbuseIPDB)؟ Geo؟ Hosting/VPS؟
  4. Content / Social engineering: Urgency ("خلال 24 ساعة")، Fear، Authority، Reward، أخطاء لغوية، تحية عامة "Dear user"، Branding مش مظبوط.
  5. URLs: النص الظاهر vs الـ href الحقيقي؟ URL shorteners؟ Redirects؟ دومين جديد؟ ← افحص في urlscan.io و VirusTotal (من غير ما تفتحه!).
  6. Attachments: النوع الحقيقي (Double extension invoice.pdf.exe)؟ Hash ← VirusTotal؟ Macros (olevba)؟ Sandbox (any.run/Joe/Hybrid Analysis)؟

17أسئلة الإنترفيو/الـ Assessment الشائعة + إجابات نموذجية

حاول تجاوب بصوت عالي الأول، وبعدين افتح الإجابة.

Networking

إيه اللي بيحصل لما تكتب google.com في المتصفح؟
DNS resolution (cache → resolver → root → TLD → authoritative) ← TCP 3-way handshake على 443 ← TLS handshake (SNI، certificate validation) ← HTTP GET ← السيرفر يرد ← المتصفح يعمل render ويطلب الـ resources. وعلى الطريق: ARP للـ gateway، NAT، Proxy/Firewall.
TCP vs UDP؟ وأمثلة؟
TCP: connection-oriented، reliable، ordered (HTTP، SSH، SMB). UDP: connectionless، أسرع، بدون ضمان (DNS، DHCP، VoIP، streaming). DNS بيستخدم TCP لما الرد كبير أو Zone transfer.
الفرق بين IDS و IPS؟ و Firewall و WAF؟
IDS بيكتشف وينبه (passive)، IPS inline وبيمنع. Firewall بيشتغل على L3/L4 (IP/Port) والـ NGFW بيوصل لـ L7. WAF متخصص في حماية الـ web apps من SQLi/XSS على L7.
Port 445 / 3389 / 53 / 88؟ وليه تهمّنا؟
445 SMB (WannaCry، lateral movement، مايتفتحش للإنترنت). 3389 RDP (brute force، ransomware initial access). 53 DNS (tunneling). 88 Kerberos (Kerberoasting، Golden ticket).
Stateful vs Stateless firewall؟
Stateful بيتابع حالة الـ connection (يعرف إن الرد ده تابع لطلب خرج) فمش محتاج rule للرد. Stateless بيفحص كل packet لوحده (زي ACLs).

Security Concepts

إيه هو الـ False Positive وإزاي تقلله؟
Alert على نشاط طبيعي. تقليله: Tuning للـ rule (thresholds، exclusions محددة)، Context (asset inventory، user roles)، Correlation مع مصادر تانية، Feedback loop مع الـ detection engineering. والأخطر منه الـ False Negative.
Encoding vs Encryption vs Hashing؟
Encoding لتغيير الشكل بدون key (Base64). Encryption للسرية وبيحتاج key وقابل للعكس (AES/RSA). Hashing one-way للـ integrity (SHA-256). الباسوردات بتتخزن Hash + Salt.
Vulnerability vs Threat vs Risk؟
Vulnerability = ضعف. Threat = حاجة ممكن تستغله. Risk = احتمال الاستغلال × الأثر. مثال: سيرفر مش متحدّث (vuln) + ransomware gang (threat) = risk عالي لو السيرفر critical.
اشرح MITRE ATT&CK والـ Cyber Kill Chain والفرق بينهم.
Kill Chain = 7 مراحل خطية عالية المستوى للهجوم. ATT&CK = knowledge base مفصّل بـ 14 Tactic (الهدف) وتحت كل واحدة Techniques/Sub-techniques (الطريقة) مبني على هجمات حقيقية، مش لازم خطي. بنستخدمه في الـ mapping، الـ detection coverage، والـ threat hunting.
SIEM vs SOAR vs EDR vs XDR؟
SIEM يجمع ويربط logs ويطلع alerts. SOAR يعمل automation للـ response (playbooks). EDR مراقبة واستجابة على الـ endpoints. XDR بيوسّع EDR لمصادر تانية (email، identity، cloud، network) في منصة واحدة.
IOC vs IOA؟
IOC دليل إن اختراق حصل (hash، IP، domain) — reactive. IOA سلوك بيدل إن هجوم شغال (Word بيشغل PowerShell) — proactive وأصعب على المهاجم يغيره (Pyramid of Pain).
إيه هو Zero Trust؟
"Never trust, always verify": مفيش ثقة تلقائية بناءً على مكانك في الشبكة. كل request يتأكد (identity، device health، context)، Least privilege، Micro-segmentation، Assume breach.
Symmetric vs Asymmetric encryption؟
Symmetric مفتاح واحد للتشفير والفك (AES) — سريع. Asymmetric زوج مفاتيح public/private (RSA/ECC) — بطيء، بيستخدم لتبادل المفاتيح والتوقيعات. TLS بيستخدم الاتنين: asymmetric لتبادل المفتاح ثم symmetric للبيانات.

Scenarios (الأهم)

يوزر بلّغ عن إيميل مريب — هتعمل إيه خطوة بخطوة؟
1) خد الإيميل كـ .eml (مش screenshot). 2) حلل الـ headers (sender، return-path، reply-to، SPF/DKIM/DMARC، originating IP). 3) حلل الـ URLs/attachments في sandbox/urlscan/VT من غير ما تفتحها. 4) Verdict. 5) لو malicious: search عن كل المستلمين ← purge ← block IOCs ← شوف في proxy/EDR مين داس أو شغّل ← reset/isolate للمتأثرين. 6) Document + شكر اليوزر (عشان يفضل يبلّغ).
يوزر داس على لينك Phishing ودخل الباسورد — إيه الـ Actions؟
Reset password + revoke sessions/tokens فوراً، راجع sign-in logs من وقت الدخول (IPs غريبة، دول)، شيك على MFA methods جديدة، inbox rules/forwarding، أي إيميلات اتبعتت من الحساب، OAuth apps اتعملها consent، وشوف لو نفس الباسورد مستخدم في مكان تاني. Block الـ phishing domain.
جالك alert إن جهاز بيكلم IP معروف إنه C2 — تعمل إيه؟
Validate (الـ IP فعلاً malicious؟ TI sources، امتى اتصنف). شوف الـ process اللي عمل الاتصال على EDR (process tree، command line، hash، parent). نطاق الاتصال (beaconing؟ bytes؟ امتى بدأ؟). لو confirmed: isolate، اجمع evidence، block IOC، hunt على باقي الأجهزة، اعرف الـ initial access، eradicate، reimage.
إزاي تفرق بين Brute force و Password spraying في اللوج؟
Brute force: يوزر واحد، باسوردات كتير، غالباً lockout (4740). Spraying: يوزرات كتير، محاولة أو اتنين لكل واحد، من نفس المصدر، على فترات. الاتنين 4625 بس الـ pattern مختلف (dc(TargetUserName)).
إزاي تعرف إن SQL injection نجح من الـ access log؟
Response size أكبر من الطبيعي بعد UNION، status 200 بعد أخطاء 500 (تحسين الـ payload)، تأخير زمني ثابت مع SLEEP، و follow-up: login ناجح للـ admin بعدها، upload، web shell. وأكد من DB logs / WAF / app logs.
Ransomware alert على سيرفر — أول 15 دقيقة؟
Isolate فوراً (network، مش shutdown لو ممكن عشان الميموري)، Escalate للـ IR/management، حدد النطاق (كام جهاز بيتشفر، share إيه)، Disable الحسابات المستخدمة، Block IOCs، احمي الـ backups (افصلها)، اجمع evidence (ransom note، sample، logs)، ماتدفعش وماتتواصلش مع المهاجم من غير قرار إداري/قانوني.
لقيت PowerShell بـ -enc — ماذا تفعل؟
Decode (Base64 → UTF-16LE). شوف الـ parent process (Office؟ SCCM؟). شوف Event 4104 للكود الكامل. استخرج IOCs (URLs، IPs). شوف network/file activity بعده. Verdict حسب السياق — مش كل -enc خبيث (بعض أدوات الإدارة بتستخدمه).
إيه اللي تعمله لو مش متأكد من Verdict؟
ماتقفلش الـ alert كـ FP. وثّق اللي لقيته والناقص، اجمع context إضافي (اسأل صاحب الجهاز/الـ IT)، Escalate لـ L2 بملخص واضح. الـ escalation الصح مش ضعف — الإغلاق الغلط هو الكارثة.
إزاي تعمل Threat Hunting؟
Hypothesis-driven: "لو مهاجم عمل X هيبان إزاي؟" (مثلاً: rundll32 بدون arguments عامل network). استخدم MITRE + TI + baseline للطبيعي، دوّر على الـ anomalies (rare processes، rare domains، stacking/long-tail analysis)، ولو لقيت حاجة → IR، ولو لأ → حوّل الـ hunt لـ detection rule.

Windows / AD

إيه هو LSASS وليه المهاجمين بيستهدفوه؟
Local Security Authority Subsystem Service — بيتعامل مع الـ authentication وبيحتفظ بالـ credentials (hashes، tickets، أحياناً cleartext) في الميموري. Dump ليه (Mimikatz، procdump، comsvcs) = سرقة credentials للـ lateral movement. الحماية: Credential Guard، LSA Protection (RunAsPPL)، ASR rules.
اشرح Kerberoasting وإزاي تكشفه.
أي domain user يقدر يطلب service ticket لأي SPN؛ التذكرة مشفرة بـ hash حساب الـ service، فالمهاجم يكسرها offline. Detection: 4769 بـ encryption 0x17 (RC4)، يوزر بيطلب tickets لـ SPNs كتير. Mitigation: باسوردات طويلة للـ service accounts (gMSA)، AES only.
Pass-the-Hash إزاي بيشتغل؟
NTLM بيقبل الـ hash بدل الباسورد، فالمهاجم اللي سرق NTLM hash يقدر يعمل authenticate من غير ما يعرف الباسورد. Detection: 4624 Logon Type 9 + seclogo، أو NTLM type 3 logons غير معتادة. Mitigation: LAPS، تقليل NTLM، Protected Users، Tiering.
إيه Event ID لـ: Log cleared / Service installed / User added to admins / Scheduled task؟
1102 / 7045 (و 4697) / 4732 (local) أو 4728 (global) أو 4756 (universal) / 4698.

Soft / Behavioral

ليه عايز تشتغل SOC Analyst؟
ركّز على: الشغف بالتحقيق وحل الألغاز، التعلم المستمر (كل يوم هجمات جديدة)، الأثر المباشر في حماية الشركة، وإنها البوابة لـ IR/Threat Hunting/Detection Engineering. واذكر حاجة عملتها فعلاً (TryHackMe SOC Level 1، LetsDefend، CyberDefenders، home lab بـ Wazuh/Splunk).
إزاي تتعامل مع Alert fatigue / Shift تقيل؟
Prioritization حسب severity و asset criticality، اقتراح tuning للـ noisy rules، automation للمهام المتكررة (SOAR)، توثيق جيد، والتواصل مع الفريق. وقت الضغط: الهدوء + اتباع الـ playbook.
إزاي بتتابع الجديد في الـ Security؟
The DFIR Report، BleepingComputer، The Hacker News، CISA advisories/KEV، MITRE updates، SANS ISC، Twitter/X و LinkedIn للباحثين، Podcasts (Darknet Diaries)، والمنصات العملية (LetsDefend/CyberDefenders/TryHackMe).
