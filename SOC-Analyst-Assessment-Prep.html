00استراتيجية الـ Assessment — إزاي تفكر وتكتب الإجابة

الـ Assessment بتاع SOC مش بيختبر إنك حافظ Event IDs وبس، هو بيختبر طريقة تفكيرك: هل بتبني استنتاج على دليل؟ هل بتعرف تفرّق بين الـ noise والـ real threat؟ هل بتعرف تكتب Report مفهوم لحد مش تقني؟

المنهجية الذهبية لأي سؤال تحليل (Triage Loop)

  1. Understand the alert: إيه اللي حصل؟ مين (user/host)؟ إمتى (timestamp + timezone)؟ منين لفين (src → dst)؟
  2. Collect evidence: استخرج كل الـ IOCs (IPs, domains, URLs, hashes, emails, filenames, user-agents).
  3. Enrich: اعمل lookup للـ IOCs (VirusTotal, AbuseIPDB, urlscan, WHOIS — عمر الدومين؟).
  4. Correlate: اربط بين مصادر مختلفة: Email → Proxy (حد داس؟) → EDR (حاجة اتنفذت؟) → Firewall/DNS (فيه C2؟).
  5. Verdict: True Positive / False Positive / Benign True Positive / محتاج Escalation — مع السبب.
  6. Scope & Impact: كام user/host اتأثر؟ فيه data خرجت؟ الـ account اتسرق؟
  7. Response: Containment (isolate, block, reset, purge) + Eradication + Recovery + Lessons learned.
💡 شكل الإجابة اللي بيبهر اللي بيصحح لما تجاوب أي سؤال تحليل اكتبه بالترتيب ده (حتى لو مش مطلوب): Summary (سطرين) ← Evidence / Findings (bullets بدليل من اللوج) ← IOCs (defanged) ← MITRE ATT&CK mapping ← Verdict + Severity ← Recommendations (Immediate / Short-term / Long-term).

قواعد ذهبية لازم تبان في إجاباتك

✅ اعمل

  • Defang أي IOC: hxxps://evil[.]com و 203.0.113[.]5
  • اذكر الـ timestamps وخلي بالك من الـ timezone (UTC vs local).
  • استشهد بالسطر نفسه من اللوج ("السطر 7 فيه POST لـ login.php بحجم 2KB…").
  • قول الـ assumptions بتاعتك صراحة لو المعلومة ناقصة.
  • فرّق بين attempt و success (Status code، bytes، follow-up activity).
  • اقترح next steps: "هشيك على EDR للـ host ده في نفس الوقت".

❌ ماتعملش

  • ماتقولش "malicious" من غير ما تقول ليه.
  • ماتعتمدش على VirusTotal = 0 detections إن الحاجة نضيفة (ممكن جديدة).
  • ماتفتحش لينكات/attachments على جهازك — sandbox بس.
  • ماتعتبرش SPF pass = إيميل آمن (الهاكر ممكن يكون عامل SPF لدومينه).
  • ماتعملش Upload لملف فيه بيانات الشركة على VirusTotal (Hash lookup الأول).
  • ماتنساش تتكلم عن الـ Business impact.

TCP vs UDP

TCP — Connection-oriented

  • 3-way handshake، Reliable، Ordered، Retransmission
  • أمثلة: HTTP/S, SSH, SMB, RDP, SMTP
  • في اللوج: تقدر تعرف هل الـ connection اكتملت ولا لأ

UDP — Connectionless

  • سريع، بدون ضمان وصول، بدون handshake
  • أمثلة: DNS (53)، DHCP، NTP، SNMP، Syslog، VoIP، QUIC
  • سهل يتعمل بيه Spoofing و Amplification DDoS

HTTP — اللي لازم تعرفه للتحليل

Methods

  • GET طلب بيانات (الـ parameters في الـ URL ← بتبان في اللوج)
  • POST إرسال بيانات (الـ body مش بيظهر في access log عادةً) — Login، Upload، Exfil
  • PUT / DELETE رفع/مسح resource — لو مفعّلين غلط = خطر
  • HEAD / OPTIONS استطلاع — كتير بيستخدموا في الـ Scanning
  • CONNECT عمل Tunnel عبر Proxy (HTTPS)

Status Codes

  • 2xx نجاح: 200 OK، 201 Created، 204
  • 3xx Redirect: 301 دائم، 302 مؤقت (بعد Login ناجح كتير!)، 304 Not modified
  • 4xx خطأ عميل: 400، 401 unauth، 403 forbidden، 404 (كتير = Dir brute force)، 405، 429 rate-limit
  • 5xx خطأ سيرفر: 500 (مع SQLi = الـ payload كسر الـ query!)، 502، 503

Headers مهمة: Host، User-Agent (sqlmap/curl/python-requests/PowerShell = مريب)، Referer (جاي منين؟)، Cookie، X-Forwarded-For (الـ IP الحقيقي ورا proxy/LB)، Content-Type، Authorization.

TLS / HTTPS باختصار

Client Hello (فيه الـ SNI = اسم الدومين بيظهر cleartext) ← Server Hello + Certificate ← Key exchange ← Encrypted traffic. فايدة للـ SOC: حتى لو مش شايف المحتوى تقدر تشوف: SNI، الـ Certificate (self-signed؟ Let's Encrypt جديد؟)، JA3/JA4 fingerprint للعميل (Cobalt Strike مثلاً ليه fingerprints معروفة).

بروتوكولات تانية سريعة

  • ARP: IP ← MAC داخل الـ LAN. ARP Spoofing = MITM (لو شفت MAC واحد لـ IPs كتير أو gateway MAC اتغير).
  • DHCP (DORA): Discover → Offer → Request → Acknowledge. مفيد لربط IP بـ Hostname في وقت معيّن!
  • NAT/PAT: IPs داخلية كتير تطلع بـ Public IP واحد ← عشان كده لازم Firewall/NAT logs عشان تعرف مين الجهاز الحقيقي.
  • ICMP: ping (Type 8 request / 0 reply)، Type 3 unreachable. Payload كبير/غريب = ICMP tunneling.
  • VLAN / Segmentation: بيقلل الـ Lateral movement.
  • Forward Proxy (بيحمي الـ users وهم طالعين للإنترنت) vs Reverse Proxy (قدام السيرفرات: Load balancing، WAF).

مفاهيم أساسية

  • Process برنامج شغال (ليه PID و Parent PID). Service process بيشتغل في الخلفية تحت services.exe.

  • UAC: بيطلب تأكيد للصلاحيات العالية. Integrity levels: Low/Medium/High/System.

SPF / DKIM / DMARC — الشرح اللي هتحتاجه

SPF

"مين الـ IPs/السيرفرات المسموح لها تبعت باسم الدومين ده؟" — TXT record. بيتشيك على دومين الـ Return-Path (مش From!).

v=spf1 ip4:192.0.2.0/24 include:spf.protection.outlook.com -all

-all Fail (رفض) · ~all SoftFail · ?all Neutral · +all أي حد (كارثة)

DKIM

توقيع رقمي على الـ headers والـ body بالـ Private key للدومين، والـ Public key في DNS. بيثبت إن الإيميل ماتعدّلش وإنه من الدومين اللي في d=.

DKIM-Signature: v=1; a=rsa-sha256;
 d=company.com; s=selector1; ...
→ selector1._domainkey.company.com

DMARC

بيربط النتيجتين بدومين الـ From (Alignment) ويقول تعمل إيه لو فشل:

_dmarc.company.com TXT
"v=DMARC1; p=reject; rua=mailto:dmarc@company.com"

p=none مراقبة بس · quarantine Spam · reject رفض

⚠️ أهم نقطة يسألوا فيها SPF/DKIM/DMARC = PASS ≠ الإيميل آمن. الهاكر ممكن يشتري دومين micros0ft-support.com ويظبطله SPF و DKIM و DMARC صح، فكله يعدي Pass. اللي بيثبتوه إن الإيميل فعلاً جاي من الدومين ده — مش إن الدومين نفسه شرعي. ونفس الكلام لو الإيميل من حساب Gmail أو حساب حقيقي اتسرق (Compromised account).

Phishing Analysis Checklist (اتبعها بالترتيب)

  1. Sender analysis: Display name vs email address؟ الدومين Lookalike؟ (عمره كام يوم — WHOIS). Reply-To / Return-Path مختلفين؟
  2. Authentication: SPF / DKIM / DMARC نتايجهم؟ و Alignment؟
  3. Received chain: الـ Originating IP إيه؟ سمعته (AbuseIPDB)؟ Geo؟ Hosting/VPS؟
  4. Content / Social engineering: Urgency ("خلال 24 ساعة")، Fear، Authority، Reward، أخطاء لغوية، تحية عامة "Dear user"، Branding مش مظبوط.
  5. URLs: النص الظاهر vs الـ href الحقيقي؟ URL shorteners؟ Redirects؟ دومين جديد؟ ← افحص في urlscan.io و VirusTotal (من غير ما تفتحه!).
  6. Attachments: النوع الحقيقي (Double extension invoice.pdf.exe)؟ Hash ← VirusTotal؟ Macros (olevba)؟ Sandbox (any.run/Joe/Hybrid Analysis)؟
  7. Scope: مين تاني استلم نفس الإيميل؟ (Search بالـ Subject/Sender/URL) — مين داس؟ (Proxy logs) — مين دخل credentials؟ (POST للدومين) — مين شغّل الملف؟ (EDR)
  8. Verdict + Actions.

🚩 Red Flags Cheat Sheet

في الـ Sender/Headers

  • Lookalike domain: rn→m، 0→o، 1/l، Punycode xn--
  • Subdomain trick: microsoft.com.secure-login.xyz (الدومين الحقيقي هو secure-login.xyz)
  • Reply-To / Return-Path مختلفين
  • SPF/DKIM/DMARC fail
  • دومين عمره أيام (WHOIS)

في المحتوى

  • Urgency / Threat / Reward
  • Generic greeting
  • Link text ≠ href، shorteners (bit.ly)، open redirect (google.com/url?q=)
  • Free hosting: web.app، firebaseapp، pages.dev، workers.dev، ipfs، sharepoint/onedrive مخترق
  • Attachment بامتداد مزدوج أو محمي بباسورد (عشان يهرب من الـ scanning)

إزاي تكشف Beaconing (C2)

  • Regularity: اتصالات على فترات ثابتة (60s، 300s) — حتى مع jitter (±10-20%) الـ pattern بيبان.
  • Same size: نفس الـ bytes كل مرة.
  • Rare destination: دومين/IP محدش تاني في الشركة بيكلمه.
  • Odd UA، IP مباشر، دومين جديد، Certificate self-signed، Long connection duration، اتصالات بالليل والجهاز idle.
  • ⚠️ FPs شائعة: Windows Update، AV updates، Teams/Slack heartbeats، NTP — كلهم periodic بس لدومينات معروفة وكتير من الأجهزة.

  4. True Positive — certutil بيستخدم كـ downloader، الملف .txt بيتحفظ كـ .exe في Public، ونفس IP الـ C2. T1105 + T1036. Isolate.
  5. False Positive / Benign — الموبايل لسه بيحاول بالباسورد القديم (stale credentials). كلّمها تحدّث الباسورد على الموبايل. (لكن اتأكد إن الـ IP فعلاً بتاعها/الـ ActiveSync device ID معروف.)
  6. Insider Threat محتمل — Data exfiltration قبل المغادرة. Escalate لـ L2 + HR/Legal حسب الـ policy، DLP review، ومايتعملش confront مباشر من الـ SOC.

17أسئلة الإنترفيو/الـ Assessment الشائعة + إجابات نموذجية

حاول تجاوب بصوت عالي الأول، وبعدين افتح الإجابة.

Networking

إيه اللي بيحصل لما تكتب google.com في المتصفح؟
DNS resolution (cache → resolver → root → TLD → authoritative) ← TCP 3-way handshake على 443 ← TLS handshake (SNI، certificate validation) ← HTTP GET ← السيرفر يرد ← المتصفح يعمل render ويطلب الـ resources. وعلى الطريق: ARP للـ gateway، NAT، Proxy/Firewall.
TCP vs UDP؟ وأمثلة؟
TCP: connection-oriented، reliable، ordered (HTTP، SSH، SMB). UDP: connectionless، أسرع، بدون ضمان (DNS، DHCP، VoIP، streaming). DNS بيستخدم TCP لما الرد كبير أو Zone transfer.
الفرق بين IDS و IPS؟ و Firewall و WAF؟
IDS بيكتشف وينبه (passive)، IPS inline وبيمنع. Firewall بيشتغل على L3/L4 (IP/Port) والـ NGFW بيوصل لـ L7. WAF متخصص في حماية الـ web apps من SQLi/XSS على L7.
Port 445 / 3389 / 53 / 88؟ وليه تهمّنا؟
445 SMB (WannaCry، lateral movement، مايتفتحش للإنترنت). 3389 RDP (brute force، ransomware initial access). 53 DNS (tunneling). 88 Kerberos (Kerberoasting، Golden ticket).
Stateful vs Stateless firewall؟
Stateful بيتابع حالة الـ connection (يعرف إن الرد ده تابع لطلب خرج) فمش محتاج rule للرد. Stateless بيفحص كل packet لوحده (زي ACLs).

Security Concepts

إيه هو الـ False Positive وإزاي تقلله؟
Alert على نشاط طبيعي. تقليله: Tuning للـ rule (thresholds، exclusions محددة)، Context (asset inventory، user roles)، Correlation مع مصادر تانية، Feedback loop مع الـ detection engineering. والأخطر منه الـ False Negative.
Encoding vs Encryption vs Hashing؟
Encoding لتغيير الشكل بدون key (Base64). Encryption للسرية وبيحتاج key وقابل للعكس (AES/RSA). Hashing one-way للـ integrity (SHA-256). الباسوردات بتتخزن Hash + Salt.
Vulnerability vs Threat vs Risk؟
Vulnerability = ضعف. Threat = حاجة ممكن تستغله. Risk = احتمال الاستغلال × الأثر. مثال: سيرفر مش متحدّث (vuln) + ransomware gang (threat) = risk عالي لو السيرفر critical.
اشرح MITRE ATT&CK والـ Cyber Kill Chain والفرق بينهم.
Kill Chain = 7 مراحل خطية عالية المستوى للهجوم. ATT&CK = knowledge base مفصّل بـ 14 Tactic (الهدف) وتحت كل واحدة Techniques/Sub-techniques (الطريقة) مبني على هجمات حقيقية، مش لازم خطي. بنستخدمه في الـ mapping، الـ detection coverage، والـ threat hunting.
SIEM vs SOAR vs EDR vs XDR؟
SIEM يجمع ويربط logs ويطلع alerts. SOAR يعمل automation للـ response (playbooks). EDR مراقبة واستجابة على الـ endpoints. XDR بيوسّع EDR لمصادر تانية (email، identity، cloud، network) في منصة واحدة.
IOC vs IOA؟
IOC دليل إن اختراق حصل (hash، IP، domain) — reactive. IOA سلوك بيدل إن هجوم شغال (Word بيشغل PowerShell) — proactive وأصعب على المهاجم يغيره (Pyramid of Pain).
إيه هو Zero Trust؟
"Never trust, always verify": مفيش ثقة تلقائية بناءً على مكانك في الشبكة. كل request يتأكد (identity، device health، context)، Least privilege، Micro-segmentation، Assume breach.
Symmetric vs Asymmetric encryption؟
Symmetric مفتاح واحد للتشفير والفك (AES) — سريع. Asymmetric زوج مفاتيح public/private (RSA/ECC) — بطيء، بيستخدم لتبادل المفاتيح والتوقيعات. TLS بيستخدم الاتنين: asymmetric لتبادل المفتاح ثم symmetric للبيانات.

Scenarios (الأهم)

يوزر بلّغ عن إيميل مريب — هتعمل إيه خطوة بخطوة؟
1) خد الإيميل كـ .eml (مش screenshot). 2) حلل الـ headers (sender، return-path، reply-to، SPF/DKIM/DMARC، originating IP). 3) حلل الـ URLs/attachments في sandbox/urlscan/VT من غير ما تفتحها. 4) Verdict. 5) لو malicious: search عن كل المستلمين ← purge ← block IOCs ← شوف في proxy/EDR مين داس أو شغّل ← reset/isolate للمتأثرين. 6) Document + شكر اليوزر (عشان يفضل يبلّغ).
يوزر داس على لينك Phishing ودخل الباسورد — إيه الـ Actions؟
Reset password + revoke sessions/tokens فوراً، راجع sign-in logs من وقت الدخول (IPs غريبة، دول)، شيك على MFA methods جديدة، inbox rules/forwarding، أي إيميلات اتبعتت من الحساب، OAuth apps اتعملها consent، وشوف لو نفس الباسورد مستخدم في مكان تاني. Block الـ phishing domain.
جالك alert إن جهاز بيكلم IP معروف إنه C2 — تعمل إيه؟
Validate (الـ IP فعلاً malicious؟ TI sources، امتى اتصنف). شوف الـ process اللي عمل الاتصال على EDR (process tree، command line، hash، parent). نطاق الاتصال (beaconing؟ bytes؟ امتى بدأ؟). لو confirmed: isolate، اجمع evidence، block IOC، hunt على باقي الأجهزة، اعرف الـ initial access، eradicate، reimage.
إزاي تفرق بين Brute force و Password spraying في اللوج؟
Brute force: يوزر واحد، باسوردات كتير، غالباً lockout (4740). Spraying: يوزرات كتير، محاولة أو اتنين لكل واحد، من نفس المصدر، على فترات. الاتنين 4625 بس الـ pattern مختلف (dc(TargetUserName)).
إزاي تعرف إن SQL injection نجح من الـ access log؟
Response size أكبر من الطبيعي بعد UNION، status 200 بعد أخطاء 500 (تحسين الـ payload)، تأخير زمني ثابت مع SLEEP، و follow-up: login ناجح للـ admin بعدها، upload، web shell. وأكد من DB logs / WAF / app logs.
Ransomware alert على سيرفر — أول 15 دقيقة؟
Isolate فوراً (network، مش shutdown لو ممكن عشان الميموري)، Escalate للـ IR/management، حدد النطاق (كام جهاز بيتشفر، share إيه)، Disable الحسابات المستخدمة، Block IOCs، احمي الـ backups (افصلها)، اجمع evidence (ransom note، sample، logs)، ماتدفعش وماتتواصلش مع المهاجم من غير قرار إداري/قانوني.
لقيت PowerShell بـ -enc — ماذا تفعل؟
Decode (Base64 → UTF-16LE). شوف الـ parent process (Office؟ SCCM؟). شوف Event 4104 للكود الكامل. استخرج IOCs (URLs، IPs). شوف network/file activity بعده. Verdict حسب السياق — مش كل -enc خبيث (بعض أدوات الإدارة بتستخدمه).
إيه اللي تعمله لو مش متأكد من Verdict؟
ماتقفلش الـ alert كـ FP. وثّق اللي لقيته والناقص، اجمع context إضافي (اسأل صاحب الجهاز/الـ IT)، Escalate لـ L2 بملخص واضح. الـ escalation الصح مش ضعف — الإغلاق الغلط هو الكارثة.
إزاي تعمل Threat Hunting؟
Hypothesis-driven: "لو مهاجم عمل X هيبان إزاي؟" (مثلاً: rundll32 بدون arguments عامل network). استخدم MITRE + TI + baseline للطبيعي، دوّر على الـ anomalies (rare processes، rare domains، stacking/long-tail analysis)، ولو لقيت حاجة → IR، ولو لأ → حوّل الـ hunt لـ detection rule.

Windows / AD

إيه هو LSASS وليه المهاجمين بيستهدفوه؟
Local Security Authority Subsystem Service — بيتعامل مع الـ authentication وبيحتفظ بالـ credentials (hashes، tickets، أحياناً cleartext) في الميموري. Dump ليه (Mimikatz، procdump، comsvcs) = سرقة credentials للـ lateral movement. الحماية: Credential Guard، LSA Protection (RunAsPPL)، ASR rules.
اشرح Kerberoasting وإزاي تكشفه.
أي domain user يقدر يطلب service ticket لأي SPN؛ التذكرة مشفرة بـ hash حساب الـ service، فالمهاجم يكسرها offline. Detection: 4769 بـ encryption 0x17 (RC4)، يوزر بيطلب tickets لـ SPNs كتير. Mitigation: باسوردات طويلة للـ service accounts (gMSA)، AES only.
Pass-the-Hash إزاي بيشتغل؟
NTLM بيقبل الـ hash بدل الباسورد، فالمهاجم اللي سرق NTLM hash يقدر يعمل authenticate من غير ما يعرف الباسورد. Detection: 4624 Logon Type 9 + seclogo، أو NTLM type 3 logons غير معتادة. Mitigation: LAPS، تقليل NTLM، Protected Users، Tiering.
إيه Event ID لـ: Log cleared / Service installed / User added to admins / Scheduled task؟
1102 / 7045 (و 4697) / 4732 (local) أو 4728 (global) أو 4756 (universal) / 4698.

Soft / Behavioral

ليه عايز تشتغل SOC Analyst؟
ركّز على: الشغف بالتحقيق وحل الألغاز، التعلم المستمر (كل يوم هجمات جديدة)، الأثر المباشر في حماية الشركة، وإنها البوابة لـ IR/Threat Hunting/Detection Engineering. واذكر حاجة عملتها فعلاً (TryHackMe SOC Level 1، LetsDefend، CyberDefenders، home lab بـ Wazuh/Splunk).
إزاي تتعامل مع Alert fatigue / Shift تقيل؟
Prioritization حسب severity و asset criticality، اقتراح tuning للـ noisy rules، automation للمهام المتكررة (SOAR)، توثيق جيد، والتواصل مع الفريق. وقت الضغط: الهدوء + اتباع الـ playbook.
إزاي بتتابع الجديد في الـ Security؟
The DFIR Report، BleepingComputer، The Hacker News، CISA advisories/KEV، MITRE updates، SANS ISC، Twitter/X و LinkedIn للباحثين، Podcasts (Darknet Diaries)، والمنصات العملية (LetsDefend/CyberDefenders/TryHackMe).

I4Windows Deep Dive للـ Interview (نقطة ضعفك ← خليها نقطة قوة)

1. إزاي Windows بيسجّل الأحداث؟

  • الـ logs متخزنة في C:\Windows\System32\winevt\Logs\*.evtx، وبتفتحها بـ Event Viewer أو Get-WinEvent.
  • أهم channels: Security (logons، accounts، audit)، System (services 7045، drivers)، Application، Microsoft-Windows-PowerShell/Operational (4104)، Microsoft-Windows-Sysmon/Operational، TerminalServices (RDP)، Windows Defender/Operational (1116 = malware detected، 1117 = action taken).
  • مش كل حاجة بتتسجل by default. لازم Audit Policy (GPO أو auditpol /get /category:*). مثلاً 4688 محتاج "Audit Process Creation" + تفعيل "Include command line in process creation events".
  • ليه Sysmon؟ لأنه بيدي تفاصيل أكتر من الـ native logs: hashes، parent command line، network connections لكل process، DNS، process access لـ LSASS.
  • الـ logs بتتبعت للـ SIEM عن طريق agent (Splunk UF، Wazuh agent، AMA في Azure) أو WEF (Windows Event Forwarding).

2. Authentication: اشرحها في دقيقة

"When a user logs in to a domain machine, Windows uses Kerberos by default. The client proves who it is to the
Domain Controller and gets a TGT (event 4768). When it needs a service, like a file share, it presents the TGT
and gets a service ticket (4769). The machine where the logon happens records 4624 with a logon type.
If Kerberos can't be used (IP instead of hostname, workgroup, legacy apps), Windows falls back to NTLM,
a challenge-response protocol validated on the DC (4776). NTLM is weaker: the hash itself works as the secret,
and that's what Pass-the-Hash abuses. LSASS handles all of this and keeps credential material in memory,
which is why attackers dump it."

3. Process vs Service vs Thread vs DLL

Processبرنامج شغال ليه memory space خاص، PID، Parent، Token (صلاحيات اليوزر)
Threadوحدة التنفيذ جوه الـ process (Injection بيعمل thread في process تانية)
ServiceProcess بيشتغل في الخلفية تحت Service Control Manager (services.exe)، وغالباً بحساب SYSTEM
DLLمكتبة كود بتتحمّل جوه process. DLL Sideloading: exe سليم وموقّع بيحمّل DLL خبيثة بنفس الاسم المتوقع من نفس الفولدر (APTs بيحبوه جداً)
Tokenهوية وصلاحيات الـ process. Token impersonation/theft = سرقة token لـ SYSTEM/admin

5. "How would you investigate a suspicious process on a Windows host?"

  1. Identity: اسمه، الـ path (System32 ولا AppData/Temp؟)، signed ولا لأ؟ hash ← VT.
  2. Lineage: مين الـ parent؟ مين الـ children؟ (Office ← PowerShell = 🚩).
  3. Command line: encoded؟ hidden؟ URLs؟ paths غريبة؟
  4. User / Integrity: شغال باسم مين؟ SYSTEM؟ ليه؟
  5. Network: بيكلّم مين؟ (Sysmon 3 / EDR network tab) و reputation الـ IP/domain.
  6. File/Registry: عمل ملفات؟ Run keys؟ scheduled tasks؟ services؟
  7. Prevalence: موجود على كام جهاز في البيئة؟ (لو على جهاز واحد بس = مريب أكتر).
  8. Timeline: إيه اللي حصل قبله بدقايق؟ (إيميل؟ download؟ logon؟)

6. أسئلة Windows سريعة وإجاباتها

Where are Windows event logs stored, and how can an attacker hide activity?
C:\Windows\System32\winevt\Logs. المهاجم يقدر يمسحها (wevtutil cl ← 1102/104)، أو يوقف الـ logging، أو يعدّل الـ audit policy (4719). الحل إن الـ logs تتبعت للـ SIEM لحظياً فمايقدرش يمسح النسخة اللي هناك.
How do you detect persistence on a Windows machine?
Autoruns (Sysinternals) بيجمع كل أماكن الـ persistence. وتدور على: Run/RunOnce keys، Scheduled tasks (4698)، Services (7045)، Startup folder، WMI subscriptions (Sysmon 19-21)، Accounts جديدة (4720)، IFEO/Winlogon changes. وفي الـ SIEM: Sysmon 13 على مسارات الـ Run keys.
What's the difference between 4624 Logon Type 3 and 10?
Type 3 = Network (SMB share، PsExec، net use)، مفيش desktop session. Type 10 = RemoteInteractive (RDP) فيه session كاملة. RDP brute force مع NLA بيبان فشله كـ Type 3.
How do you detect credential dumping?
Sysmon 10 (process access لـ lsass.exe بـ access masks زي 0x1010/0x1410/0x1FFFFF)، command lines زي procdump -ma lsass و comsvcs.dll MiniDump، reg save HKLM\SAM، ملفات .dmp في أماكن غريبة، تنبيهات EDR.
svchost.exe looks suspicious. How do you check?
لازم: parent = services.exe، path = C:\Windows\System32\svchost.exe، فيه -k <group> في الـ command line، signed by Microsoft، والـ user SYSTEM / LOCAL SERVICE / NETWORK SERVICE (أو اليوزر لبعض الـ per-user services). أي اختلاف (parent explorer، path في AppData، اسم svch0st) = مريب.
What is PowerShell logging and why does it matter?
3 أنواع: Module logging (4103)، Script Block logging (4104، بيسجّل الكود بعد فك الـ obfuscation)، و Transcription (نص كامل للجلسة). مهمة لأن PowerShell أكتر أداة بيستغلها المهاجمين. ولازم تاخد بالك من محاولات downgrade لـ PowerShell v2 (powershell -version 2) عشان يهرب من الـ logging و AMSI.

أسئلة Phishing سريعة

SPF passed but it's still phishing. How?
SPF بيثبت إن الـ IP مسموحله يبعت باسم دومين الـ Return-Path بس. المهاجم ممكن: يمتلك الدومين (lookalike) ويظبط SPF، أو يبعت من خدمة شرعية (Gmail، SendGrid)، أو يستخدم حساب مخترق. وكمان SPF مش بيتشيك على الـ From اللي اليوزر شايفه، ودي شغلة DMARC alignment.
What is DMARC alignment?
إن الدومين في الـ From header يطابق (relaxed = نفس الـ organizational domain، strict = نفس الدومين بالظبط) الدومين اللي عدّى SPF (Return-Path) أو اللي عدّى DKIM (d=). لو ولا واحد aligned يبقى DMARC fail حتى لو SPF pass.
How do you analyze a QR code phishing (quishing) email?
فك الـ QR من غير ما تفتحه بالموبايل (أدوات decode أو CyberChef "Parse QR Code")، وحلّل الـ URL زي أي لينك. خطورته إنه بيعدّي من URL scanning في الـ gateway (لأنه صورة) ويخلّي اليوزر يفتحه على موبايل شخصي برا حماية الشركة.
A user says "I clicked but didn't enter anything." What do you do?
ماتصدقش بالكامل ولا تكذّب. اتحقق: Proxy (فيه POST؟ download؟)، EDR (حاجة اتنفذت بعد الضغط؟)، Sign-in logs (login غريب؟). لو كله نضيف: document + awareness. ولو الصفحة كانت AiTM، مجرد الدخول ممكن يكون عدّى بالـ SSO، فشيّك sign-ins كويس.
What do you check if the email has a password-protected ZIP?
الباسورد غالباً في نص الإيميل، والهدف إن الـ gateway مايقدرش يفحص المحتوى. الموضوع ده لوحده suspicious. فكّه في sandbox وشوف جواه إيه (.js، .vbs، .lnk، .exe، .iso).

أسئلة SIEM سريعة

What is a SIEM and why do we need it?
Security Information and Event Management. بيجمع الـ logs من كل مكان في مكان واحد، يعمل normalize، يربط events من مصادر مختلفة (correlation)، يطلع alerts، ويدعم التحقيق والـ compliance والـ retention. من غيره هتدخل على 20 console عشان تحقق في incident واحد.
What's the difference between a log, an event, an alert and an incident?
Log = سجل خام. Event = حدث له معنى (logon). Alert = event (أو مجموعة) طابقت rule. Incident = alert(s) اتأكد إنها تهديد حقيقي ومحتاجة response.
A log source stopped sending logs. What do you do?
ده alert مهم (blind spot). اتأكد من آخر event وصل إمتى، الـ agent/forwarder شغال؟ الشبكة؟ تغيير config/certificate؟ إبلاغ العميل/فريق الـ engineering. وفكّر أمنياً: ممكن يكون المهاجم وقّف الـ agent (Defense evasion)، خصوصاً لو حصل بعد alert مريبة.
Agent-based vs agentless collection?
Agent: تفاصيل أكتر، reliable، بيعمل buffering لو الشبكة قطعت، بس محتاج installation وإدارة. Agentless (Syslog، API، WEF): أسهل، مناسب للـ network devices والـ cloud، بس ممكن يضيّع events (UDP syslog مفيهوش ضمان).
What is UEBA?
User & Entity Behavior Analytics: بيعمل baseline لسلوك كل user/host ويطلع alerts على الانحراف (login في وقت غريب، data أكتر من المعتاد، access لسيرفر عمره ما دخله). مفيد للـ insider threat والـ compromised accounts.
What is SOAR and give an example playbook.
Security Orchestration, Automation & Response. مثال phishing playbook: user reports email ← استخراج IOCs تلقائياً ← enrichment (VT, urlscan) ← لو malicious: search & purge من كل الـ mailboxes + block sender/URL + فتح ticket ← إشعار للـ analyst للمراجعة. بيوفر وقت الـ L1 للتحليل الحقيقي.

Tuning: إزاي تقلل الـ False Positives صح

✅ الصح

  • Exclusion محدد: (IP + user + process + وقت) مش IP لوحده.
  • Allowlist بتاريخ انتهاء ومراجعة.
  • ظبط الـ threshold بالـ data التاريخية (baseline).
  • زوّد context: severity أعلى للـ critical assets / privileged users.
  • Aggregation / Suppression: alert واحدة بدل 500 لنفس الحدث.
  • Risk-based alerting: كل حاجة تزود score، والـ alert تطلع لما الـ score يعدّي حد.

  • Exclude لـ powershell.exe كله أو subnet كامل.

  • ترفع الـ threshold لحد ما تبطل تمسك حاجة.
  • تقفل alerts كـ FP من غير تحقيق عشان الـ queue.

أسئلة Rules سريعة

How would you write a rule to detect password spraying?
Data: 4625 (أو Entra sign-in logs بـ error 50126). Group by source IP، count distinct target usernames، threshold مثلاً ≥ 15 users في 10-30 دقيقة، مع عدد محاولات قليل لكل user. وأحسن: alert أعلى لو فيه success من نفس الـ IP. Exclusions: VPN/NAT egress IPs الكبيرة محتاجة تعامل خاص لأن ناس كتير طالعين من IP واحد.
Signature-based vs behavior-based (anomaly) detection?
Signature: بيطابق pattern معروف (hash، string، IOC). دقيق وقليل الـ FP، بس مابيمسكش الجديد. Behavior/Anomaly: بيدور على سلوك غير طبيعي أو TTPs. بيمسك الجديد (zero-days) بس الـ FP بتاعه أعلى. الأحسن الاتنين مع بعض.
A rule generates 300 alerts a day, all FP. What do you do?
ماقفلهاش. أحلل الـ 300: إيه المشترك؟ (process/user/host واحد؟ job مجدول؟). أتأكد من صاحب النشاط إنه legit، وأعمل exclusion محدد بالشروط المشتركة دي مع توثيق ومراجعة، أو أعدّل الـ logic/threshold. وأتابع بعد التعديل إن الـ rule لسه بتمسك السيناريو الأصلي (test).
What's the difference between YARA, Sigma and Snort?
YARA للملفات والـ memory (patterns جوه malware). Sigma للـ logs وبتتحول لأي SIEM query. Snort/Suricata للـ network packets (IDS/IPS rules).

EDR بيشوف إزاي؟ (سؤال عميق بيميّزك)

  • Agent/Sensor على الجهاز، فيه جزء في الـ kernel (driver).
  • Kernel callbacks: Windows بيبلّغ الـ driver عند إنشاء process/thread أو تحميل image (DLL) أو تعديل registry.
  • Minifilter driver: بيراقب عمليات الملفات (create/write/rename)، وده مفيد جداً لكشف الـ ransomware.
  • ETW (Event Tracing for Windows)، ومنه ETW Threat-Intelligence: تفاصيل زي memory allocation في processes تانية.
  • AMSI integration: فحص الـ scripts بعد فك التشفير.
  • User-mode hooks (في بعض المنتجات) على APIs حساسة.
  • الـ telemetry بتتبعت لـ cloud للـ analytics والـ correlation والـ threat intel، والـ detections بترجعلك في الـ console.
  • المهاجمين بيحاولوا: يوقفوا الـ agent، unhooking، BYOVD (Bring Your Own Vulnerable Driver) عشان يقتلوا الـ EDR من الـ kernel. عشان كده "sensor went offline" alert مهمة.

"Walk me through triaging an EDR alert"

"First I read the detection: what rule fired, what tactic, what severity, which host and user.
Then I check context: is it a server or a workstation, is the user privileged, is this asset critical for the client?
Next I open the process tree: parent, child, command line, file path, signature and hash. I decode anything
encoded and check the hash and any network destinations against threat intel.
Then I look around the timeline: what happened minutes before (an email, a download, a logon) and after
(network connections, persistence, lateral movement).
I check prevalence: has this hash or command line appeared on other hosts?
Then I decide. If it's benign, like a known admin tool, I document why and suggest tuning. If it's malicious,
I contain according to the runbook (isolate, kill, quarantine), escalate, notify the client and hunt for the same IOCs elsewhere."

أسئلة EDR سريعة

EDR alert says "Detected" not "Blocked/Prevented". Does it matter?
جداً. Detected = الـ EDR شاف بس النشاط ممكن يكون كمل، يعني محتاج تدخل فوري. Prevented/Blocked = اتمنع، بس لسه لازم تعرف إزاي وصل لهنا (الـ initial access) ولو فيه حاجات تانية ماتمنعتش.
Should you shut down an infected machine?
غالباً لأ. اعمل network isolation بدل الـ shutdown عشان تحافظ على الـ memory (keys، injected code، network connections) للتحقيق. الاستثناء: ransomware بيشفر حالياً ومفيش isolation متاح، ساعتها إيقاف الضرر أولى.
The EDR agent on a host went offline right after a suspicious alert. What do you think?
احتمال Defense Evasion (المهاجم وقّف/شال الـ agent، T1562.001). اتأكد من مصادر تانية (Firewall، DNS، AD logons للجهاز)، Escalate، وتعامل كأنه compromised لحد ما يثبت العكس. وطبعاً ممكن يكون سبب عادي (الجهاز اتقفل)، فاتأكد.
How do you know if a detection on a signed Microsoft binary is malicious?
الـ binary سليم بس الاستخدام هو اللي مريب (LOLBins). بص على: الـ parent، الـ command line arguments، الـ paths (Public/Temp)، الـ network activity، المستخدم، والوقت. مثال: rundll32.exe سليم، بس rundll32 comsvcs.dll MiniDump = credential dumping.

I11Behavioral (STAR) + أسئلة تسألها إنت + يوم الـ Interview

طريقة STAR

  • Situation: الموقف (جملة واحدة)
  • Task: كان مطلوب منك إيه
  • Action: إنت عملت إيه بالتحديد (أطول جزء)
  • Result: النتيجة + اتعلمت إيه

مفيش خبرة شغل؟ استخدم: BTL1 exam، LetsDefend cases، مشاريع الجامعة، شغل جماعي، تدريب، أي شغل (حتى برا الـ IT) فيه ضغط أو عملاء.

قصص جاهزة (املاها بتفاصيلك الحقيقية)

"Tell me about a challenging investigation."
S: In LetsDefend I got an alert for [e.g. a phishing email with an Excel attachment].
T: I had to decide if it was malicious and whether the user was affected.
A: I analyzed the headers (SPF fail, lookalike domain), extracted the attachment hash and found a macro that
   launched PowerShell. Then I checked the endpoint logs and saw the user had opened it: there was an outbound
   connection to [IP]. So I contained the host, documented the IOCs and closed it as a true positive.
R: Correct verdict. It also taught me that the email is only half the investigation: you have to confirm
   impact on the endpoint and the network.
"Tell me about a time you worked under pressure." (BTL1)
S: The BTL1 exam is a 24-hour practical incident-response investigation.
T: Answer the questions on a full incident using SIEM, forensics and phishing analysis within the time limit.
A: I planned my time, started with what I was confident about, kept notes of every finding with timestamps,
   and when I got stuck I moved on and came back later instead of burning hours.
R: I passed [with X%]. I learned that structured notes and prioritization matter more than speed,
   which applies directly to working an alert queue under SLA.
"Tell me about a mistake you made."
S: Early in my LetsDefend practice I closed an alert as a false positive because the file hash was clean on VirusTotal.
T: I had to understand why my verdict was wrong after reviewing the case.
A: I realized the file was new, so it had no detections yet, and the process behavior was clearly malicious
   (Office spawning PowerShell). I changed my approach: behavior and context first, reputation is only one input.
R: Since then I never close an alert on a single data point. I check at least two independent sources.

المهم: غلطة حقيقية، صغيرة، وإنت اتعلمت منها وغيرت طريقتك. ماتقولش "مابغلطش".

"How do you explain a technical issue to a non-technical person?"
قصة عن شرح حاجة لأهلك/صحابك/عميل: استخدم تشبيه ("الـ phishing زي حد يتصل بيك ويقولك أنا من البنك…")، ركّز على الأثر والمطلوب منهم مش التفاصيل التقنية. وده مهم جداً في MSSP لأنك هتكلم عملاء.
"How do you handle many alerts at once?"
Prioritize حسب severity + SLA + asset criticality ← خلص الـ critical الأول ← لو الحمل أكبر منك بلّغ الـ shift lead بدري (مش بعد ما الـ SLA يتخرق) ← ماتقفلش alerts بسرعة من غير تحقيق ← دوّر على alerts مرتبطة ببعض (ممكن تكون incident واحد).
"Tell me about a disagreement with a teammate."
ركّز على: سمعت وجهة نظره، رجعنا للدليل/الـ data مش للرأي، وصلنا لقرار، والعلاقة فضلت كويسة. في SOC: "إحنا مختلفين على الـ verdict؟ نبص على الـ evidence ونعمل escalate لو لسه مش متفقين".
"How do you keep learning?"
اذكر حاجات فعلية: LetsDefend، BTL1، والـ blogs اللي بتقراها (The DFIR Report مثال ممتاز، فيه incidents حقيقية بالتفصيل وبالـ TTPs)، CISA advisories، BleepingComputer، Podcasts. ولو فيه حاجة اتعلمتها الأسبوع ده اذكرها، بيبان إنك متابع بجد.
